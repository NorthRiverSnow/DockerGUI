# 仕様: 端末

`common.md` の約束を前提にする。

## 開き方

コンテナの一覧の行から開く。**動作中のコンテナでだけ開ける**（`containers.md`）。

端末の画面は同時に複数開ける。開いた画面の数だけ、エンジンとの通信路が増える。

## 実行するコマンド

開くときに、コンテナの中で実行するコマンドを決める。

**`/bin/bash` を試し、失敗したら `/bin/sh` を試す。**

**why: 小さいイメージには `bash` が入っていない。** `alpine` を元にしたイメージには
`sh` しか無いことが多い。`bash` を決め打ちにすると、開けないコンテナが多く出る。

どちらも失敗した場合は、**実行するコマンドを利用者が入力できる欄を出す。**

```
web-1 で bash と sh のどちらも実行できませんでした
コンテナの中で実行するコマンド [                    ] ［開く］
```

## 画面の構成

```
┌──────────────────────────────────────────────────────┐
│ web-1   /bin/bash                          ［閉じる］ │
├──────────────────────────────────────────────────────┤
│ # ls                                                 │
│ app  node_modules  package.json                      │
│ # ▏                                                  │
└──────────────────────────────────────────────────────┘
```

画面の先頭に、コンテナの名前と、実行しているコマンドを出す。
**実行しているコマンドを出すのは、`bash` と `sh` のどちらで開いたかで使える機能が違うため。**

## 入力と出力

- 利用者の入力をコンテナへ送り、コンテナの出力を画面に出す
- 端末の制御文字（色、カーソルの移動、画面の消去）を解釈して表示する
- 文字の符号化は UTF-8 として扱う

## 窓の大きさを変えたとき

**画面の大きさが変わったら、新しい行数と桁数をエンジンへ送る。**

**why: 送らないと、コンテナの中のプログラムは古い大きさのまま描画する。**
`vi` のような画面を描くプログラムで、表示が崩れる。

## 閉じたとき

［閉じる］を押すか画面を閉じると、**コンテナの中で実行しているコマンドを終了させ、
エンジンとの通信路を閉じる。**

**why: 閉じないと、コンテナの中のコマンドが動き続け、通信路のための子プロセスも残る**
（設計方針の原則 8）。

## コンテナが停止したとき

端末を開いている間にコンテナが停止すると、実行しているコマンドも終了する。

```
web-1 が停止したため、端末を閉じました
```

**画面は開いたままにして、停止するまでの出力を読めるようにする。** 入力は受け付けない。

**why: 停止の直前に出ていた内容が、停止の原因を調べる材料になる。**
画面ごと閉じると、読む前に消える。

## 接続が切れたとき

接続が切れると端末の通信路も切れる（`connection.md`）。
**端末は開き直しになる。** 再接続しても、切れる前に実行していたコマンドは続いていない。

```
接続が切れたため、端末を閉じました
［開き直す］
```

**why: 端末の通信路は、接続のたびに新しく開くもの。**
再接続した後の通信路は別のものなので、切れる前の状態には戻せない。

## コピーと貼り付け

- 画面で選んだ文字をコピーできる
- 貼り付けた文字を、そのままコンテナへ送る

**複数行を貼り付けるときは、実行の前に確認を出す。**

```
3 行を貼り付けます。改行ごとにコマンドとして実行されます。
              [ やめる ]  [ 貼り付ける ]
```

**why: 複数行の貼り付けは、意図せず複数のコマンドを実行させる。**
末尾に改行が含まれていると、利用者が内容を確かめる前に最後のコマンドまで実行される。
