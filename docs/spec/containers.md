# 仕様: コンテナ

`common.md` の約束を前提にする。

## 一覧

### 出す列

| 列 | 内容 |
| --- | --- |
| 状態 | 「状態の呼び方」のとおり |
| 名前 | コンテナの名前 |
| イメージ | コンテナを作ったイメージの名前とタグ |
| ポート | 外に公開しているポートの対応（例: `8080 → 80`）。無ければ空。IPv4 と IPv6 で同じ対応を公開していても、1 つにまとめて出す |
| 時間 | 動作中のコンテナは起動してからの経過。動作中でないコンテナは終了してからの経過 |

**時間は、今からの経過で出す**（`common.md` の「表記」の「一覧の時刻」）。一度も起動していないコンテナは空にする。

コンテナ ID は一覧に出さない。**名前があるコンテナを ID で見分ける利用者はいない。**
ID は詳細の画面に出す。

### 状態の呼び方

Engine API が返す状態は英語で、そのまま出すと利用者が意味を調べることになる。
**日本語で表示するときは、日本語の言葉に置き換える。**
**英語で表示するときは、Docker の言葉の先頭を大文字にして出す**（`common.md` の「Docker の英語の言葉」）。

| Engine API が返す状態 | 日本語で出す言葉 | 英語で出す言葉 | コンテナは動いているか |
| --- | --- | --- | --- |
| `running` | 動作中 | `Running` | 動いている |
| `paused` | 一時停止中 | `Paused` | 止まっている（再開できる） |
| `restarting` | 再起動中 | `Restarting` | 起動し直している途中 |
| `created` | 未起動 | `Created` | 動いていない |
| `exited`（終了コード 0） | 正常終了 | `Exited (0)` | 動いていない |
| `exited`（終了コード 0 以外） | 異常終了（コード 137） | `Exited (137)` | 動いていない |
| `removing` | 削除中 | `Removing` | 動いていない |
| `dead` | 削除失敗 | `Dead` | 動いていない |

**状態は、色の付いたアイコンと、状態の呼び方の文を並べて出す。** 動いているもの（動作中）は緑、止めてあるもの（一時停止中）は黄（ライトの配色では橙。`design/renderer.md` の「色と背景のコントラスト」）、終わったもの（未起動、正常終了）は灰、
調べる必要があるもの（異常終了、削除失敗）は赤にする。色とアイコンの組み合わせは、Storybook の「コンテナ/一覧」の「読み込み済み（すべての状態）」を正とする（`common.md` の「見た目の正は Storybook」）。

**`exited` は終了コードで呼び分ける。** 英語で表示するときは、`docker ps` の `STATUS` の列と同じく、終了コードを括弧に入れて付ける（開発機で確認。`Exited (255) 9 days ago` と出た）。終了コードが 0 かどうかで、
利用者が次にすることが変わる——0 なら正常に終わっており、0 以外ならログを読むことになる。
**一覧を見た時点で「調べる必要があるかどうか」が分かる形にする。**

### `dead` は異常終了ではない

**`dead` は、エンジンがコンテナの削除を始めて、完了できずに残っている状態。**
異常終了（`exited` で終了コードが 0 以外）とは別のもので、混同すると原因の調べ先を間違える。

`dead` のコンテナは、DockerGUI からは起動も停止も削除もできない。
詳細の画面に、**エンジンを起動し直すと削除できることが多い**と案内を出す。

### 並び順

**動作中のコンテナを先に出し、動作中のコンテナの中では名前の順に並べる。**

**why: 一覧を開く目的の多くは、いま動作中のコンテナを見ることにある。**
終了したコンテナが上に並ぶと、目的のコンテナを探すことになる。

### 絞り込み

名前とイメージの名前の両方を対象に、入力した文字を含むコンテナだけを出す。

あわせて、**動作中でないコンテナを隠す切り替えを置く。** 既定は隠さない。

一覧の上に、絞り込みの入力と、切り替えを並べる。

| 部品 | 出す文 |
| --- | --- |
| 絞り込みの入力 | 入力の中の薄い文 `名前かイメージで絞り込む` |
| 切り替え | チェックボックスと `動作中でないコンテナを隠す` |

**絞り込みに当てはまるコンテナが無いときは、一覧の代わりに `絞り込みに当てはまるコンテナがありません` を出す。**
絞り込みの入力と切り替えは、出したままにする。「1 件も無いとき」の文を出すと、コンテナがあるのに無いと読める。

**切り替えは、アプリを開き直しても元のままにする**（`settings.md` の「設定の画面に出すもの」）。絞り込みの入力は覚えない。

**why: 終了したコンテナは溜まる。** 一覧が終了したコンテナで埋まると、
動作中のコンテナが画面に収まらなくなる。

### 1 件も無いとき

```
コンテナが 1 件もありません
Compose の画面からプロジェクトを起動すると、コンテナが増えます
```

## 詳細

一覧の行を選ぶと、コンテナの詳細を出す。

| 項目 | 内容 |
| --- | --- |
| コンテナ ID | 全体を出す（`common.md` の「利用者がコピーして使いたい値」） |
| 名前 | コンテナの名前 |
| イメージ | イメージの名前とタグ、イメージ ID |
| 状態 | 状態と、終了した場合は終了コード |
| コマンド | コンテナが実行しているコマンド |
| 作成した日時 | 年月日と時分秒 |
| 起動した日時 | 年月日と時分秒。まだ起動していない場合は空 |
| ポート | 外に公開しているポートの対応 |
| マウント | ボリュームまたはホストのパスと、コンテナの中のパス |
| ネットワーク | つながっているネットワークの名前と IP アドレス。**ネットワークごとに 1 つずつ出す** |
| 再起動の設定 | `no` `always` `on-failure` などの設定 |
| 環境変数 | 値を伏せて出し、［表示］ を置く（「環境変数は既定で隠す」を参照） |
| ラベル | キーと値 |

### 環境変数は既定で隠す

環境変数の値を伏せて出し、［表示］のボタンを置く。ボタンを押すと値を出す。

```
DATABASE_URL   ●●●●●●●●●●                       ［表示］
```

**why: 環境変数にはパスワードと API のキーが入っていることが多い。**
画面を共有しながら作業することと、画面を録画することがあるため、
利用者が開く操作をするまで値を出さない。

## 操作

| 操作 | 押すボタン | 出す状態 | 確認 |
| --- | --- | --- | --- |
| 起動 | ［起動］ | 正常終了、異常終了、未起動 | 無し |
| 一時停止 | ［一時停止］ | 動作中 | 無し |
| 再開 | ［再開］ | 一時停止中 | 無し |
| 停止 | ［停止］ | 動作中、一時停止中 | 無し |
| 強制停止 | ［強制停止］ | **停止処理中だけ**（「停止は待たされる」を参照） | 無し |
| 再起動 | ［再起動］ | 動作中 | 無し |
| 削除 | ［削除］ | 削除失敗（`dead`）以外のすべての状態 | **有り** |

**出す状態に当てはまらないボタンは、出さない**（`common.md` の「その状態で使えないボタンは、出さない」）。

**行のボタンは、行の右端にアイコンで並べる。** マウスを重ねると、ボタンの名前を出す。
アイコンには色を付ける。起動と再開は緑、一時停止は黄、再起動は青で、操作の後の状態（動作中、一時停止中、再起動中）と同じ色にする。停止は、コンテナの中のプロセスを終わらせるので赤にする。
色とアイコンの組み合わせは、Storybook の「コンテナ/一覧」の「読み込み済み（すべての状態）」を正とする。
動作中のコンテナには、ログ・ターミナル・削除を含めて 6 つのボタンが並ぶ。文字のボタンにすると、一覧の幅の多くをボタンが使う。

```
● 動作中    web-1   nginx:1.27   8080 → 80   3 分前      ［一時停止］［停止］［再起動］
○ 正常終了  db-1    postgres:16               1 時間前                      ［起動］
```

停止処理中の知らせと、操作の失敗の知らせを、まとめて**「行の知らせ」**と呼ぶ。
**行の知らせは、コンテナの行の 2 段目に、字下げして出す**（操作の失敗は `common.md` の「失敗の置き場所」の「操作した対象の行」）。
1 段目と 2 段目の間に線を引かず、マウスを重ねたときの色も 2 段をまとめて変え、1 つの行に見せる。

**why: 別の行に見せない。** 別の行に見えると、知らせがどのコンテナのものかを、上の行を見て確かめることになる。

| 行の知らせ | 出している間 | ボタン |
| --- | --- | --- |
| 停止処理中の知らせ | 停止の応答を待っている間（「停止は待たされる」） | ［強制停止］ |
| 操作の失敗の知らせ | 操作が失敗してから、［閉じる］ を押すまで。同じコンテナで操作をやり直したときと、コンテナが一覧から消えたときも消す | ［閉じる］ |

```
● 動作中    web-1   nginx:1.27   8080 → 80   3 分前      ［一時停止］［停止］［再起動］
  ! コンテナ web-1 を停止できませんでした。<エンジンが返した文>                ［閉じる］
```

操作の共通の約束（実行中は同じ操作を受け付けない、成功は知らせない、失敗は画面に残す）は
`common.md` に書いてある。

### 一時停止と停止の違い

**一時停止は、メモリの中身を残したまま、CPU だけを空ける操作。**

| | 停止 | 一時停止 |
| --- | --- | --- |
| コンテナの中のプロセス | 終了する | 止まったまま残る |
| メモリの中身 | 消える | 残る |
| CPU | 空く | 空く |
| 動かし直すとき | ［起動］。コンテナの中のアプリの起動を待つ | ［再開］。止めた所からすぐ続く |

**一時停止を使う場面は、動かし直すまでの時間を短くしたいとき。** たとえば、データを読み込むのに
数分かかるコンテナを、別の重い作業の間だけ止めておく場合。停止すると、再開のときに
データの読み込みからやり直しになる。

**一時停止してもメモリは空かない。** メモリを空けたいときは停止する。
［一時停止］ と ［停止］ を並べて出すので、詳細の画面に、一時停止ではメモリが空かないことを添える。

**確認は出さない。** 一時停止も再開も、取り返しのつかない操作ではない。

**DockerGUI の外で一時停止されたコンテナも、［再開］ で動かせる。**

### 停止は待たされる

停止の要求を受けたエンジンは、コンテナに `SIGTERM` を送り、
待ってから `SIGKILL` で強制的に終了させる。
**待ち時間の既定はエンジンが決めていて、Linux のコンテナでは 10 秒。**

停止の完了を待っている間の行の状態を**「停止処理中」**と呼ぶ。
**停止処理中は、行の右端のボタンを消し、行の 2 段目に、行の知らせとして次の文を出す**。並びは `common.md` の「待たせるときの表示」に従う。

```
● 動作中    web-1   nginx:1.27   8080 → 80   3 分前
  web-1 を停止しています…  経過 00:04  ［強制停止］
```

**why: 行の右端に出さない。** 停止処理中の文は、ボタンより長い。行の右端に出すと、列が広がり、ほかの列が横に動く。

**停止処理中だけ ［強制停止］ を出す。** 押すと待ち時間を 0 にして、
エンジンがコンテナを即座に強制終了する。

**中止のボタンは置かない。** エンジンはコンテナに `SIGTERM` を送った時点で停止を始めていて、
送った合図を取り消す手段が無い（`common.md` の「待たせるときの表示」の例外）。
待てない利用者のために、代わりに ［強制停止］ を置く。

**why: 終了の合図を無視するコンテナがある。** 10 秒待つと分かっていても、
待てない場面がある。逆に、待てば正常に終了するコンテナを毎回強制終了させると、
書き込みの途中でデータが壊れる。**既定は待ち、利用者が選んだときだけ強制終了する。**

### 削除の確認

```
┌────────────────────────┐
│ コンテナ web-1 を削除します。                  │
│ 元に戻せません。                               │
│                                                │
│                      [ やめる ]  [ 削除する ]  │
└────────────────────────┘
```

**動作中のコンテナを削除する場合は、停止も行うことを確認の画面に表示する。**

```
┌─────────────────────────┐
│ コンテナ web-1 を削除します。                    │
│ web-1 は動作中なので、停止してから削除します。   │
│ 元に戻せません。                                 │
│                                                  │
│                      [ やめる ]  [ 削除する ]    │
└─────────────────────────┘
```

**why: 動作中のコンテナの削除は、停止を伴う。**
停止することを書かないと、利用者は動作中のコンテナが止まると考えずに削除する。

### まとめて操作する

一覧で複数のコンテナを選び、起動・一時停止・再開・停止・再起動・削除をまとめて実行できる。

- **選んだコンテナのうち、操作できる状態のものだけを実行の対象にする。**
  動作中のコンテナと終了したコンテナを選んで［起動］を押した場合、
  終了したコンテナだけを起動する。
- **削除の確認には、件数と対象の名前を全部並べる**（`common.md`）。
- **一部が失敗しても、残りは実行する。** 失敗したコンテナの名前と原因を並べて出す。

**why: まとめて操作する場面では、対象が多い。**
1 件の失敗で全部が止まると、どこまで実行されたのかを利用者が確かめることになる。

## ログとターミナルを開く

一覧の行から、ログの画面とターミナルの画面を開く。

| 開くもの | 開ける状態 | 仕様 |
| --- | --- | --- |
| ログ | すべての状態 | `logs.md` |
| ターミナル | 動作中 | `terminal.md` |

**終了したコンテナのログは読める。** コンテナが終了していても、エンジンはログを保持している。
**why: 利用者がログを読みたい場面の多くは、コンテナが終了した後にある。**

**ターミナルは動作中のコンテナでしか開けない。** 動作中でないコンテナには、
コマンドを実行する相手がいない。動作中でないコンテナには、ターミナルを開くボタンを出さない
（`common.md` の「その状態で使えないボタンは、出さない」）。

## 一覧の更新

コンテナの状態が変わった時点で一覧を更新する。一定の間隔で取り直すことはしない（設計方針の原則 5）。

更新の対象は、コンテナの作成・起動・停止・強制終了・削除、および健康状態の変化。
