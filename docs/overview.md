# 概要

## DockerGUI とは

**DockerGUI** は、Docker を画面から操作するデスクトップアプリ。
コンテナの一覧を見て、起動・停止し、ログを読み、コンテナの中でコマンドを実行する——
Docker を使う人が毎日繰り返す操作を、ターミナルに打ち込まずに済ませる。

## Docker の構成

Docker は 2 つの部分に分かれている。

| 部分 | 何をするか |
| --- | --- |
| **エンジン** | コンテナを動かす。コンテナ・イメージ・ボリューム・ネットワークを保持する |
| **クライアント** | エンジンに操作を依頼する。`docker` コマンドはクライアントの 1 つ |

**DockerGUI はクライアントの側にある。** DockerGUI 自身はコンテナを動かさない。
利用者が画面でコンテナの起動のボタンを押すと、**DockerGUI はエンジンに
「選ばれたコンテナを起動してください」と依頼し、エンジンが選ばれたコンテナを起動する。**

依頼のしかたは 2 通りある。**DockerGUI は Engine API を直接呼び出す。**
Compose の操作だけは Engine API に無いため、`docker compose` コマンドを実行する。

### イメージとコンテナは別のもの

| 言葉 | 何か | 動くか |
| --- | --- | --- |
| **イメージ** | コンテナのもとになる型。中身は変わらない | **動かない** |
| **コンテナ** | イメージから作った実体 | **起動・停止する** |

**イメージを起動することはできない。** `docker run node:22` は、
`node:22` のイメージから新しいコンテナを作り、作ったコンテナを起動している。
**DockerGUI のイメージの画面にも、起動のボタンは無い。**

**イメージは、コンテナを起動するときに自動で取得される。**
手元に無ければエンジンが取りに行くので、DockerGUI でイメージを取得するのは、
**同じタグの新しいイメージに入れ替えるとき**が主になる
（`spec/images.md` の「イメージを取得する場面」を参照）。

### ボリュームとネットワークは、コンテナに付くもの

コンテナには、**ボリューム**と**ネットワーク**が付く。どちらもコンテナを作るときに繋がれる。

| 言葉 | 何か | 付いていないとどうなるか |
| --- | --- | --- |
| **ボリューム** | コンテナの外にあるファイルの置き場所 | コンテナを削除すると、コンテナの中に書いたファイルも消える |
| **ネットワーク** | コンテナ同士をつなぐ通信路 | 他のコンテナと通信できない |

**同じネットワークにいるコンテナは、相手をコンテナの名前で呼べる。**
コンテナの IP アドレスは作り直すたびに変わるので、**名前で呼べることがネットワークの主な役目**
（開発機で確認。同じネットワークのコンテナには名前で届き、
別のネットワークのコンテナには `bad address` で届かない）。

**ブラウザからコンテナに繋ぐのは、ネットワークではなくポートの公開の働き。**
コンテナの一覧の「ポート」の列に出る `8080 → 80` がそれにあたる。

- **ネットワーク** = コンテナ同士がつながる
- **ポートの公開** = 利用者のパソコンからコンテナにつながる

**ボリュームもネットワークも、多くの場合 Compose が作る。**
Compose はプロジェクトごとにネットワークを 1 つ作り、サービスを全部そこに入れる。
DockerGUI から作る手段は置かない（`spec/volumes-networks.md` の「DockerGUI からは作らない」を参照）。

### エンジンは 1 台の機械に 2 つ以上あることがある

macOS では colima と Docker Desktop が、Windows では Docker Desktop と、
WSL のディストロそれぞれに入れた Docker が、同じ機械に同居できる。

**コンテナ・イメージ・ボリュームは、エンジンごとに別々に保持される。**
あるエンジンが持つコンテナは、別のエンジンからは見えない。

```
colima のエンジン            Docker Desktop のエンジン
  ├─ コンテナ web-1          ├─ コンテナ postgres
  ├─ コンテナ db-1           └─ イメージ redis:7
  └─ イメージ node:22
```

DockerGUI が**いまつないでいるエンジンを「接続先」と呼ぶ。**
接続先を切り替えると、画面に出るコンテナとイメージは丸ごと入れ替わる。

DockerGUI が同時につなぐ接続先は 1 つ（「対象にしないもの」を参照）。

## 誰が、どの場面で使うか

Docker を日常的に使う開発者が、自分の開発機で使う。

想定する場面は次の 3 つ。

| 場面 | ターミナルで打つ場合 | DockerGUI で行う場合 |
| --- | --- | --- |
| 動いているコンテナを確かめる | `docker ps` を打ち、横に長い出力を読む | 一覧の画面を見る。状態の変化は自動で反映される |
| 異常終了したコンテナのログを読む | `docker logs -f <id>` を打つ。コンテナ ID を先に調べる | 一覧から行を選び、ログの画面を開く |
| コンテナの中を調べる | `docker exec -it <id> sh` を打つ | 一覧から行を選び、ターミナルの画面を開く |

## 対象環境

| OS | Docker の構成 | アプリが動く場所 |
| --- | --- | --- |
| macOS | Docker Desktop、colima、その他 unix ソケットを使うもの | macOS |
| Windows | Docker Desktop（WSL2 バックエンド） | Windows |
| Windows | WSL のディストロに直接入れた Docker Engine（Docker Desktop を使わない） | Windows |

**Windows でも、アプリは Windows のアプリとして動く。** アプリを WSL の中で動かす構成は対象にしない
（「対象にしないもの」を参照）。

Docker への接続先は、決め打ちにせず**利用者の環境から探して決める**。
macOS では colima のように `/var/run/docker.sock` を使わない構成があり、パスを決め打ちにすると接続できない。

## できること

| 対象 | できること |
| --- | --- |
| コンテナ | 一覧の表示、起動、停止、再起動、削除 |
| ログ | 選んだコンテナのログの表示。新しい行が出たら自動で続きを表示する |
| ターミナル | 選んだコンテナの中でコマンドを実行する |
| イメージ | 一覧の表示、取得（pull）、削除 |
| ボリューム | 一覧の表示 |
| ネットワーク | 一覧の表示 |
| Compose | プロジェクトの一覧、起動（up）、停止（down）、サービスごとの状態の表示 |
| エンジン | Docker のエンジンを起動・停止する。起動は既定で自動（設定でボタンに変えられる） |
| 診断 | Docker に接続できないときに、何を試して何が失敗したかを表示する |

## 対象にしないもの

**作らないと決めておかないと、設計が対象外の機能を見越した形に膨らむ。**

| 対象にしないもの | 理由 |
| --- | --- |
| インストーラの作成、コード署名、公証 | 当面は開発者本人の開発機で動けばよい。署名には有償の登録と証明書が要る |
| 遠隔のホストへの接続（SSH や TCP 越しの Docker） | 対象の場面が開発機の中の Docker に限られる |
| アプリを WSL の中で動かす構成（WSLg） | 利用者に WSLg の設定を求めることになる。Windows のアプリとして動かせば設定が要らない |
| イメージの構築（build） | 構築は Dockerfile を編集しながら行う作業で、エディタとターミナルの側にある |
| レジストリへのログインと push | 取得（pull）だけを対象にする |
| Kubernetes と Swarm | 対象の場面に出てこない |
| 複数の Docker への同時接続 | 接続は常に 1 つ。切り替えは行えるが、同時には繋がない |

## 用語

**用語の表の言葉を、コードの名前とドキュメントの両方で使う。** 言い換えを増やすと、
同じものを指しているかどうかが読めなくなる。

| 言葉 | 意味 |
| --- | --- |
| イメージ | コンテナのもとになる型（「イメージとコンテナは別のもの」を参照） |
| コンテナ | イメージから作った実体。起動・停止する（「イメージとコンテナは別のもの」を参照） |
| ボリューム | コンテナの外にあるファイルの置き場所（「ボリュームとネットワークは、コンテナに付くもの」を参照） |
| ネットワーク | コンテナ同士をつなぐ通信路（「ボリュームとネットワークは、コンテナに付くもの」を参照） |
| Docker Engine | コンテナを動かしているサーバ。以下「エンジン」（「Docker の構成」を参照） |
| 接続先 | DockerGUI がつないでいるエンジン（「Docker の構成」を参照） |
| Engine API | エンジンが提供する HTTP の API。DockerGUI は Engine API を直接呼び出す |
| コンテキスト | Docker CLI が持つ接続先の設定。`docker context ls` で並ぶもの |
| 接続方式 | エンジンに繋ぐ経路。「ソケット」と「子プロセス」の 2 つがある（`design.md` を参照） |
| ディストロ | WSL の中に入っている Linux の環境。`wsl.exe -l` で並ぶもの |
| 診断 | 接続に失敗したときに、何を試して何が失敗したかを調べて表示する機能 |
| 追従 | ログの画面で、新しい行が出たら自動で末尾まで表示を進めること |
