# 日本語を書く

**書いた本人以外が読んで、同じ意味に取れる文にする。**

日本語は主語と目的語を省略でき、多義語が多い。**放っておくと、書いた本人にしか読めない文が残る。**

---

## 1. 主語と目的語を省略しない

**「何が」「何を」を書く。** 動詞ごとに、目的語が何かを確かめる。

```
✗ 外した項目は、開き直しても外れている
○ 一覧の項目のチェックを外すと、画面を開き直してもその項目のチェックは外れたまま

✗ 項目を押すと選択が保存される
○ 一覧の行を押すと、その項目の選択が端末に保存される

✗ リセットは押した項目だけを未着手に戻す
○ リセットのボタンは、押した項目だけを未着手に戻す

✗ 自動で回る
○ テストで検証する

✗ 差し替えると食い違う
○ テスト用のデータを渡すと、画面ごとに件数が食い違う
```

**特に危ないのは「外す」「消す」「戻す」「出る」「変わる」。** 目的語が無いと複数の意味になる。

---

## 2. 多義語を使わない

```
✗ lint で落とす         ○ lint エラーにする
✗ テストが落ちる         ○ テストが失敗する
✗ 空行を落とす           ○ 空行を削除する
✗ コントラストが落ちる    ○ コントラストが下がる
✗ HMR で拾われない       ○ HMR の対象外
✗ テストを流す           ○ テストを実行する
✗ ルールが効く           ○ ルールが適用される
✗ 例外を上げる           ○ 例外を throw する
✗ サーバを上げる         ○ サーバを起動する
✗ 検証を通す             ○ 検証が正常終了する
```

**「落とす」は特に禁止。** lint エラーか、要素の削除か、値の低下か、区別が付かない。

---

## 3. 因果を書く。状況だけで終わらせない

**「何が起きるか → だからどうするか」の形にする。**

```
✗ 実データに 3 本ある
○ 連続する改行をまとめると行が 1 つ減り、間を空けて区切っていた文が地続きに見える
```

**調査した時点の数値は書かない。** 「153 行中 4 本」「最長 41 字」は元データが変われば嘘になる。
残すのは、いつでも成り立つ因果のほう。

---

## 4. 当然の疑問に先回りする

読む人が最初に思う疑問に答えていないと、その説明は使えない。

```
✗ 空の要素にも min-height を与える
○ 中身が空だと高さが 0 になり、隣の列と行がずれる。min-height で 1 行ぶんを確保する
```

---

## 5. 経緯を書かない

**「以前は X だったが Y にした」は git log の役目。** ドキュメントは現行の姿だけを書く。

```
✗ 当初は接続画面を出していたが、api が無い環境では意味が無いので消した
○ api が居なければ接続画面を出さない
```

---

## 書いた後の点検

**1 文ずつ、次の順に当てはめる。**

1. 主語は書いてあるか。**「何が」**
2. 目的語は書いてあるか。**「何を」**
3. 多義語を使っていないか
4. 状況で終わっていないか。**因果になっているか**
5. 経緯が混ざっていないか

**とくに見落としやすいのは、自分が書いた規則の文そのもの。**
「主語を省略しない」と書いた文で主語を省略していることがある。
