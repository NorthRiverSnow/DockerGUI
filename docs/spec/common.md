# 仕様: 画面に共通する約束

**各機能の仕様は、共通の約束を前提にする。** 共通の約束を機能ごとの仕様に書き写さない。

## 画面の構成

ウィンドウは 3 つの領域に分かれる。

```
            ┌─────────────────────────────┐
状態バー    │ 接続先: colima              ［停止］ ［配色］ ［日本語］ │
            ├────────┬────────────────────┤
対象の一覧  │ コンテナ       │                                        │
            │ イメージ       │                                        │
            │ ボリューム     │                                        │
            │ ネットワーク   │ 一覧と詳細                             │
            │ Compose        │                                        │
            │ ディスク       │                                        │
            │ ──────   │                                        │
            │ 診断           │                                        │
            │ 設定           │                                        │
            └────────┴────────────────────┘
```

左の一覧で対象を選ぶと、右に選ばれた対象の一覧が出る。**同時に開ける対象は 1 つ。**

**アプリを開いた直後は、左の一覧で「コンテナ」を選んだ状態にする。**
`overview.md` の「誰が、どの場面で使うか」の 3 つの場面は、どれもコンテナの一覧から始まる。

上部の領域を**状態バー**と呼ぶ。接続の状態と、画面全体に関わる知らせを状態バーに出す。
状態バーの右端には、配色を選ぶボタンと、画面の言語を選ぶボタンを置く（「配色」「画面の言語」）。

### ログとターミナルのタブ

**ログとターミナルの画面は、右の領域のタブとして開く。** タブは右の領域の上に横に並べる。

```
            ┌───────┬──────────────────────────────┐
タブ        │ コンテナ     │ ［一覧］［web-1 のログ ×］［db-1 のターミナル ×］        │
            │              ├──────────────────────────────┤
タブの中身  │ イメージ     │ 2026-09-17 10:02:41.220  Listening on port 3000            │
            │ ボリューム   │ 2026-09-17 10:02:41.318  GET / 200                         │
            │ ネットワーク │ ...                                                        │
            │ Compose      │                                                            │
            └───────┴──────────────────────────────┘
```

| タブ | 中身 | 閉じられるか |
| --- | --- | --- |
| ［一覧］ | 左の一覧で選んだ対象の一覧と詳細 | 閉じられない。常に一番左にある |
| `<コンテナの名前> のログ` | `logs.md` のログの画面 | 閉じられる |
| `<コンテナの名前> のターミナル` | `terminal.md` のターミナルの画面 | 閉じられる |

図の `×` は、タブの ［閉じる］。画面に出すのは絵のアイコン（「図は配置だけを表す」）。

**why: ログとターミナルには、右の領域の高さを全部使わせる。**
異常終了したコンテナのログを読む場面では、一覧よりログを広く見られることが大事で、
`vi` のように画面全体を使うプログラムも、高さが足りないと使いにくい。

**タブの振る舞い**

- 一覧の行からログかターミナルを開くと、タブを右端に追加し、追加したタブを選んだ状態にする
- **同じコンテナのログを 2 回開いても、タブを増やさない。** すでにあるタブを選んだ状態にする。
  同じ中身のタブが 2 つあると、別のものが 2 つあるように見える。ターミナルも同じ
- 左の一覧で対象を選ぶと、［一覧］ のタブを選んだ状態にする。ログとターミナルのタブは閉じない
- 選んでいるタブを閉じると、閉じたタブの左のタブを選んだ状態にする
- **接続先を切り替えたときは、ログとターミナルのタブをすべて閉じる。**
  接続先を切り替えるとストリームをすべて閉じる（`connection.md` の「接続先を変えたとき」）ので、
  前の接続先のコンテナのタブを残しても、中身を読み直せない

**タブを閉じるキーは置かない。** `Ctrl + W` はターミナルの中のプログラムが使う
（`terminal.md` の「キーはコンテナへ送る」）。

### 図は配置だけを表す

**docs の図は、何が画面にあって、どこに並ぶかを表す。**
色・余白・字の大きさ・アイコンの絵柄は表さない。

- 図の中の ［…］ は、押せるもの。実際にはアイコンだけのボタンもある
- 図の中の `[x]` は、入切の切り替え
- 図の中の `↓` `!` は、行の状態を表すアイコン
- 図の中の文は、日本語で表示したときの文。英語で表示したときの幅は表さない（「画面の言語」）

**見た目の正は Storybook**（`design-policy.md`）。
**図を画面の写真に差し替えない**——写真は差分が読めず、古くなっても気づけない。

## 一覧の振る舞い

### 自動で更新する

一覧は、Docker 側の状態が変わった時点で更新される。**利用者が更新の操作をする必要は無い。**
更新のためのボタンを置かない。

更新で行が増減しても、次の 2 つを守る。

- **選んでいる行は選ばれたまま**にする。選んでいる行が消えた場合だけ、選択を外す。
- **メニューを開いている間は、並び順を変えない。** 押そうとした項目が動くと、
  利用者は意図しない行を操作する。

### 並び順と絞り込み

| 項目 | 既定 |
| --- | --- |
| 並び順 | 機能ごとの仕様で定める |
| 絞り込み | 名前の一部を入力して絞る。大文字と小文字を区別しない |

絞り込みの入力は、左の一覧で対象を切り替えても**消さない**。同じ名前で別の対象を見ることが多い。

### 1 件も無いとき

「1 件もありません」の文に加えて、**何をすれば増えるかを併記する**
（例: コンテナの一覧なら「Compose の画面からプロジェクトを起動すると、コンテナが増えます」）。
空の画面に説明が無いと、利用者はアプリが壊れていると考える。

### 一覧の状態

**一覧を出す画面（コンテナ、イメージ、ボリューム、ネットワーク、Compose）は、一覧の場所に次の 4 つの状態を持つ。**

| 状態 | 一覧の場所に出すもの | ボタン |
| --- | --- | --- |
| 読み込み中 | スケルトン | 無し |
| 読み込み済み | 一覧。0 件なら「1 件も無いとき」の文 | 機能ごとの仕様のとおり |
| 取得失敗 | 失敗の文（「失敗の見せ方」） | ［もう一度読み込む］ |
| 未接続 | `コンテナの一覧を出すには、Docker エンジンに接続してください。状態バーからエンジンを起動するか、接続してください。` | 無し |

**スケルトン**は、読み込みが終わる前に、一覧の行の形だけを帯で並べておく仮の表示。

| 状態 | どうやってその状態になるか |
| --- | --- |
| 読み込み中 | 左の一覧で対象を選んだ。接続した。「取得失敗」で ［もう一度読み込む］ を押した |
| 読み込み済み | 読み込みが終わった |
| 取得失敗 | 読み込みで、エンジンが失敗を返した |
| 未接続 | 接続していないときに対象を選んだ。表示している間に接続が切れた |

**「読み込み済み」の一覧が更新されるときは、「読み込み中」に戻さない。**
一覧を出したまま、新しい中身に入れ替える（「自動で更新する」）。

**why: 読み込み中に、文ではなくスケルトンを出す。** 一覧の読み込みは短く、文を出すと一瞬だけ出て消え、
画面がちらつく。スケルトンは一覧と同じ形なので、読み込みが終わっても画面の配置が動かない。

**why: 読み込み中に中止のボタンを置かない。** 一覧を見るために対象を選んだ利用者に、
読み込みを途中でやめる理由が無い。別の対象を見たくなったら、左の一覧で別の対象を選べばよい
（「待たせるときの表示」の例外）。

**「未接続」の文の対象の名前は、画面ごとに変える**（「コンテナの一覧」「イメージの一覧」など）。

## 操作の約束

### 取り返しのつかない操作は、確認を挟む

削除のように元に戻せない操作は、実行の前に確認を出す。

```
┌────────────────────────┐
│ コンテナ web-1 を削除します。                  │
│ 元に戻せません。                               │
│                                                │
│                      [ やめる ]  [ 削除する ]  │
└────────────────────────┘
```

- **対象の名前を必ず表示する。** 「本当によろしいですか」だけでは、何が消えるか分からない。
- **最初にフォーカスが当たるのは「やめる」。** Enter を押しただけで削除されないようにする。
- 複数を選んで削除する場合は、**件数と、対象の名前の一覧**を表示する。

### その状態で使えないボタンは、出さない

**行と詳細に置くボタンは、その状態で押せるものだけを出す。** 押せないボタンを残しておくと、
押せるボタンと押せないボタンが混ざって、どれが使えるか読めなくなる。

**押せない状態で出してよいのは、機能の仕様に理由を書いたものだけ。**
理由の無い「押せない状態」を作らない。

### 実行中は、同じ操作を受け付けない

操作を始めてから結果が返るまで、操作した行の同じ操作は押せない状態にする。
**why: Docker への要求は即座に終わらない。** 押せる状態のままだと、
利用者は反応が無いと考えて何度も押し、同じ要求が重なる。

### 結果の知らせ方

| 結果 | 知らせ方 |
| --- | --- |
| 成功 | **知らせない。** 一覧の表示が変わることで分かる |
| 失敗 | 画面に残る形で出す。利用者が閉じるまで消えない |

**why: 成功の知らせは数が多く、読む必要が無いのに画面を覆う。**
一方、失敗の知らせが自動で消えると、席を外していた利用者は失敗に気づけない。

#### 表示が変わらない成功は、知らせる

**成功しても画面の表示が変わらない操作だけは、成功を知らせる。**
知らせないと、利用者は操作が動いたのかどうかを判断できない。

| 操作 | 知らせ方を決めている仕様 |
| --- | --- |
| 値のコピー | 「コピーしたことを知らせる」 |
| すでに最新だったイメージの取得 | `images.md` の「すでに最新だったとき」 |
| すでに一覧にあるプロジェクトの追加 | `compose.md` の「すでに一覧にある設定ファイルを選んだとき」 |
| ログのファイルへの保存 | `logs.md` の「保存の状態」 |

**機能の仕様で「成功は知らせない」を当てはめる前に、表示が本当に変わるかを確かめる。**

## 待たせるときの表示

**利用者を待たせる処理では、次の 4 つを同じ並びで出す。** 画面が違っても並びを変えない。

1. **対象の名前**（エンジンの名前、コンテナの名前）
2. **何をしているか**（「〜しています…」）
3. **実行しているコマンド**（括弧の中に、そのままの形で）
4. **経過した時間**

```
Ubuntu-22.04 を試しています…（wsl.exe -d Ubuntu-22.04 -e docker version）  経過 00:03  ［中止］
web-1 のログを読み込んでいます…                           経過 00:02  ［中止］
```

**コマンドを実行していない処理では、括弧を出さない。**
Engine API を呼ぶだけの処理には、括弧の中に書くコマンドが無い。

**why: 待たされている理由が分かる。** 加えて、コマンドをそのまま出せば、
利用者が失敗の状況を読んで伝えられる。開発者は Windows の環境を持っていないので、
利用者が読み取れる形で出すことに意味がある。

**待たせる処理には、必ず中止のボタンを置く。**
中止できない処理は、利用者が終わるまで何もできない時間になる。

**例外は 4 つだけ。**

| 例外 | 中止のボタンの代わり |
| --- | --- |
| エンジンの起動 | 無し。`connection.md` の「起動中は中止できない」 |
| エンジンへの再接続 | 無し。10 秒で打ち切る（`connection.md` の「再接続の繰り返し」） |
| エンジンが取り消しを受け付けない処理 | 機能の仕様に、取り消せない理由と、代わりに押せるボタンを書く |
| 一覧の読み込み | 無し。スケルトンを出す（「一覧の状態」） |

## 失敗の見せ方

### 文面の形

失敗の表示は、**次の 3 つを番号の順で書く。**

1. **何ができなかったか**（対象の名前を含める）
2. **原因**
3. **次にできること**（あれば）

```
✗ エラーが発生しました
✗ 操作に失敗しました（500）

○ コンテナ web-1 を停止できませんでした。
  10 秒待っても応答がありません。
  ［強制停止］
```

**why: 利用者が知りたいのは、次に何をすればよいか。** 原因だけを出すと、
利用者は次の行動を自分で考えることになる。

### 想定していない失敗

**DockerGUI の不具合のように、起き方を決めていない失敗は、どの画面でも同じ文で出す**
（`design-policy.md` の原則 9「想定した失敗と、想定していない失敗」）。

```
コンテナ web-1 を停止できませんでした。
DockerGUI の中で、想定していない失敗が起きました。
ログを開発者に送ってください。            ［ログのフォルダを開く］
```

「文面の形」の 3 つに当てはめると、次のとおり。

| 文面の形 | 想定していない失敗で出すもの |
| --- | --- |
| 何ができなかったか | 機能ごとの文と同じ（対象の名前を含める） |
| 原因 | `DockerGUI の中で、想定していない失敗が起きました`。**スタックトレースは出さない** |
| 次にできること | ログを開発者に送る。［ログのフォルダを開く］ で、ログのファイルがあるフォルダを OS のファイルの画面で開く |

**why: 原因を出しても、利用者は次にすることを決められない。** 開発者が読むものはログに書いてあるので、
ログを見つける手段を出す。

### 失敗の置き場所

| 失敗の種類 | どこに出すか |
| --- | --- |
| Docker に接続できない | 状態バー（`connection.md`） |
| 1 つの対象への操作が失敗した | 操作した対象の行、または画面に残る通知 |
| 一覧を取得できない | 一覧を表示する場所へ、一覧の代わりに出す（「一覧の状態」の「取得失敗」） |

## 画面の言語

**画面の文を、日本語と英語で表示する。**

### 言語を選ぶ

**状態バーの 1 行目の右端に、いまの画面の言語の国旗のボタンを置く**（「画面の構成」の図の ［日本語］）。
ボタンを押すと、選べる言語のメニューが開く。ボタンの名前（読み上げと、マウスを重ねたときに出す文）は、言語の名前にする。

| 言語 | 国旗 |
| --- | --- |
| 日本語 | 日本 |
| English | アメリカ |

**英語の旗は、アメリカの旗にする。** 画面の英語の文は、アメリカの綴り（`color` など）で書くので、文と旗をそろえる。
**メニューの項目には、国旗と言語の名前を並べる。** 「自動」には、国旗の代わりに地球のアイコンを出す。

| 選べる値 | 表示する言語 |
| --- | --- |
| 自動 | OS の言語が日本語なら日本語。それ以外なら英語 |
| 日本語 | 日本語 |
| English | 英語 |

**既定は「自動」。** 選んだ言語は保存し、アプリを開き直しても同じ言語で表示する
（`settings.md` の「画面の切り替えは、アプリを開き直しても元のままにする」）。

**選んだ言語は、すぐ適用する。** 開いているすべての画面の文と、メニューバーのメニューを切り替える。
アプリを開き直さない。

**ボタンは、接続の状態によらず、常に出す。**

**why: 状態バーは、どの画面を開いていても見える。**
画面の言語を読めない利用者でも、言語を変える場所を探さずに済む。

**「自動」のときに英語で表示する why: DockerGUI は日本語と英語の文しか持たない。**
日本語を読めない利用者には、英語のほうが読める見込みが高い。

**メニューでは、言語の名前を、その言語で表示する**（「日本語」「English」）。
「自動」だけは、いまの画面の言語で表示する。

**why: 言語の名前をいまの画面の言語で表示すると、画面の言語を読めない利用者は、自分の言語を見つけられない。**

**設定の画面の「配色・言語」でも選べる**（`settings.md` の「配色・言語」）。

**設定の ［既定に戻す］ を押しても、画面の言語は戻さない**（`settings.md` の「既定に戻す」）。
［既定に戻す］ を押すのは、変えた設定のせいで動きがおかしくなったときで、画面の言語は動きに関わらない。
**戻すと、英語を選んでいた利用者の画面が、日本語の OS では日本語に変わり、読めなくなる。**

### 仕様に書く画面の文

**仕様に書く画面の文は、日本語の文だけ。** 英語の文は、日本語の文の訳として実装のときに作り、仕様には書かない。

**why: 同じ文を 2 つの言語で仕様に書くと、片方だけを直したときに、2 つの文が食い違う。**
日本語の文を正にしておけば、英語の文が食い違ったときに、どちらを直すかで迷わない。

### 訳さないもの

| 訳さないもの | 例 | 理由 |
| --- | --- | --- |
| Docker が返した文 | 失敗したときに Engine API が返した理由の文 | Docker が作った文で、DockerGUI からは中身を変えられない |
| 利用者のデータ | コンテナの名前、ログの中身、ターミナルの中身 | 利用者が作ったもので、訳すと元の値と違うものになる |
| コマンドと、コピーして使う値 | `colima start`、ファイルのパス | 訳すと、そのまま貼り付けても動かなくなる |

### Docker の英語の言葉

**日本語で表示するときに Docker の英語の言葉を置き換える箇所は、英語で表示するときは置き換えず、Docker の言葉を出す。**

| 箇所 | 決めている仕様 |
| --- | --- |
| コンテナの状態（`running` `exited` など） | `containers.md` の「状態の呼び方」 |
| イメージの取得の、層の状態（`Downloading` など） | `images.md` の「層ごとの進捗は、詳細に出す」 |
| Compose の進み具合（`Container` `Started` など） | `compose.md` の「起動と停止の進み具合」 |

**why: 英語で表示するときに Docker の言葉を別の英語に言い換えると、`docker` コマンドの出力や Docker の文書と言葉が食い違う。**
利用者が画面の言葉で検索しても、Docker の文書で同じ言葉が見つからなくなる。

**DockerGUI が作った言葉は、英語で表示するときも訳す。** Compose のプロジェクトの「一部だけ動作中」は、
Docker が返した `Status` の文字列を DockerGUI がまとめた言葉で、Docker の言葉ではない（`compose.md` の「プロジェクトの状態」）。
失敗の文も、Docker が返した理由の文を DockerGUI が書き換えた文なので訳す。括弧に入れて残す Docker の文だけは訳さない。

### 文の長さは、言語によって変わる

**ボタンと列の幅を、文の字数から決め打ちにしない。** 英語の文は、同じ意味の日本語の文より長いことが多い。
幅を日本語の文に合わせて決めると、英語で表示したときに文が途中で切れる。

### 英語のボタンの名前

**動詞で始め、最初の 1 語の先頭だけを大文字にする**（「Start」「Force stop」「Close」）。
確認の画面のボタンも同じ形にする（「Cancel」「Delete」）。
日本語の「削除」と「削除する」のような書き分け（「ボタンの名前」）は、英語では要らない。英語の動詞は、画面に置くボタンでも確認の画面でも同じ形になる。

## 配色

**配色は、画面の背景と文字の色の組み合わせ。** ライト（明るい背景に暗い文字）とダーク（暗い背景に明るい文字）の 2 つを持つ。

### 配色を選ぶ

**状態バーの 1 行目の、画面の言語を選ぶボタンの左に、配色のボタンを置く**（「画面の構成」の図の ［配色］）。
**ボタンを押すと、ライトとダークを切り替える。** ボタンには、いま表示している配色のアイコン（ライトは太陽、ダークは月）を出す。

| 場面 | 表示する配色 |
| --- | --- |
| 一度もボタンを押していない | OS の配色に合わせる。DockerGUI を開いている間に OS の配色が変わったら、DockerGUI の配色もすぐ変える |
| ボタンを押した | 押して切り替えた配色。保存し、アプリを開き直しても同じ配色で表示する。OS の配色が変わっても変えない |

**why: 1 回押すだけで切り替わる。** 選べる値のメニューを開いて選ぶ手間が無い。
「自動」を選べる形にすると、「自動」を選んでいるときに、いまライトとダークのどちらで表示しているかが、ボタンから分からない。

**OS の配色に合わせる状態に戻すときは、設定の画面の「配色・言語」で「OS に合わせる」を選ぶ**（`settings.md` の「配色・言語」）。
状態バーのボタンは、ライトとダークを切り替えるだけで、OS に合わせる状態には戻さない。

**切り替えた配色は、すぐ適用する。** アプリを開き直さない。

**ボタンは、接続の状態によらず、常に出す。**

**why: 状態バーは、どの画面を開いていても見える。** 暗い部屋で画面がまぶしいときに、開いている画面を離れずに切り替えられる。

**ログとターミナルの本文も、配色に合わせる。** 本文だけが明るいままだと、画面の大部分が明るいままになり、ダークにした意味が無い。

**設定の ［既定に戻す］ を押しても、配色は戻さない**（`settings.md` の「既定に戻す」）。
画面の言語と同じく、配色は動きに関わらない（「言語を選ぶ」）。

## 表記

| 対象 | 表記 |
| --- | --- |
| 一覧の時刻 | 今からの経過（「3 分前」「2 日前」）。英語では英語の書き方にする（「3 minutes ago」） |
| 詳細とログの時刻 | 年月日と時分秒（`2026-09-25 14:03:12`）。**言語によらず同じ形にする。** ログは他の記録と突き合わせるので、絶対の時刻が要る |
| 大きさ | Docker CLI の表示と食い違わない形にする（実装時に `docker images` の出力と突き合わせて確かめる） |
| ID と 16 進数の名前 | 切り詰めて出すときは先頭 12 文字。詳細の画面では全体 |

### ボタンの名前

| ボタンの種類 | 名前の形 | 例 |
| --- | --- | --- |
| 画面に置くボタン（状態バー、見出し、行、詳細） | **漢語の動詞は「する」を付けない。** 和語の動詞はそのまま | ［起動］［削除］［強制停止］［閉じる］［開く］ |
| 確認の画面のボタン | 起きることを言い切る形 | [ やめる ] [ 削除する ] |

**why: 画面に置くボタンは数が多く、短いほうが並べて読める。**
確認の画面は、利用者が押す前に何が起きるかを読む場所なので、動詞の形で言い切る。

**画面に置くボタンの名前には「選ぶ」ではなく「選択」を使う**（［接続方式を選択］）。

### 利用者がコピーして使いたい値

**一覧でも詳細でも、コピーできるようにする。**

| 値 | 貼り付ける先の例 |
| --- | --- |
| 名前（コンテナ、イメージ、ボリューム、ネットワーク） | `docker` コマンドの引数、Compose のファイル |
| コンテナ ID、イメージ ID、ネットワーク ID | `docker` コマンドの引数 |
| イメージのダイジェスト | Dockerfile と Compose のファイル |
| **IP アドレス** | ブラウザ、通信を試すコマンド、アプリの設定 |

**why: 打ち間違えても気づけない値だから。** 16 進数の ID と IP アドレスは、
1 文字違っても形が正しく見える。**打ち間違えたときに出るのは「見つからない」だけで、
どこを間違えたかは出ない。**

#### コピーされるのは、元の値の全体

**画面に出している文字ではなく、切り詰める前の値をコピーする。**

- 一覧が ID の先頭 12 文字だけを出していても、コピーすると全体が入る
- 中央を省略した長い名前（「長い名前」を参照）も、コピーすると省略していない名前が入る

**why: 切り詰めているのは画面の幅の都合で、DockerGUI は元の値を持っている。**
出している文字をそのままコピーさせると、**貼り付けた値がどこでも使えない。**

#### コピーのアイコンを、値の右に置く

**コピーできる値の右に、コピーのアイコンを置く。** 押すと、左の値をコピーする。

```
┌──────────────────────────────────────────┐
│ コンテナ ID    1bf72c7aee3ed68c6b48d6b8185eb87b85dfa70c6      ［コピー］           │
│ 名前           web-1                                          ［コピー］           │
│ ネットワーク   cypher-quiz_default ［コピー］   172.19.0.3    ［コピー］           │
│ 作成した日時   2026-09-09 11:58:23                                                 │
└──────────────────────────────────────────┘
```

**画面に出すのは、絵のアイコン。** 図の中で ［コピー］ と書いているのは、
**docs の図が配置だけを表すため**（「図は配置だけを表す」を参照）。

**1 つの項目に値が 2 つあるなら、アイコンも 2 つ置く。**
ネットワークの項目にはネットワークの名前と IP アドレスが並ぶので、
アイコンが 1 つだと、どちらがコピーされるか読めない。

**コピーして使う値の無い項目には、アイコンを置かない**（作成した日時、大きさ、状態）。

| 場所 | 押すもの | 出すとき | コピーされるもの |
| --- | --- | --- | --- |
| 詳細 | ［コピー］ | **常に出す** | ［コピー］ の左の値 |
| 一覧 | ［コピー］ | **選んでいる行にだけ出す** | 行の名前 |

**why: 一覧の全部の行にアイコンを出すと、画面がアイコンで埋まる。**
選んでいる行は 1 行だけなので、アイコンも 1 つで済む。

**マウスを乗せている間だけ出す形にはしない。**
キーボードだけで操作する利用者と、画面を触って操作する利用者に、アイコンが出てこない。
キーボードからは `Cmd/Ctrl + C` でもコピーできる（「キーボードの操作」）。

#### コピーしたことを知らせる

**アイコンを押したら、アイコンの場所に `コピーしました` を 2 秒間出す。**

```
┌──────────────────────────────────────────┐
│ 名前           web-1                                         コピーしました        │
└──────────────────────────────────────────┘
```

**why: コピーは画面に何の変化も起こさない**（「表示が変わらない成功は、知らせる」）。
知らせないと、利用者はコピーできたかどうかを、別の場所に貼り付けて確かめることになる。

#### キーボードからコピーする

**`Cmd/Ctrl + C` は、文字を選んでいるときは、選んでいる文字をコピーする。**
OS の標準の動きを変えない。

**文字を選んでいないときだけ、画面ごとに決めた値をコピーする。**

| 画面 | 文字を選んでいないときの `Cmd/Ctrl + C` |
| --- | --- |
| 一覧 | 選んでいる行の名前をコピーする |
| 詳細 | **何もしない。** 値ごとに置いたアイコンを使う |
| 診断 | 全項目の結果をコピーする（`connection.md` の「コピーの手段」） |
| ターミナル | `terminal.md` の「キーはコンテナへ送る」のとおり。Windows では `Ctrl + Shift + C` |

**why: 詳細で何もしないのは、コピーする値を 1 つに決められないから。**
詳細には値が何個も並ぶので、キーだけでは、どれをコピーするか伝わらない。

### 長い名前

**中央を省略し、先頭と末尾を残す。**

```
✗ ghcr.io/example-organization/very-long-service-…
○ ghcr.io/example-organ…/very-long-service:v1.2.3
```

**why: 末尾にタグと版が付く。** 末尾を削ると、どの版かが読めなくなる。

## キーボードの操作

| キー | 動き |
| --- | --- |
| `↑` `↓` | 一覧の行を移動する |
| `Enter` | 選んでいる行の詳細を開く |
| `Esc` | 開いている詳細・確認・メニューを閉じる |
| `Cmd/Ctrl + F` | 絞り込みの入力にフォーカスを移す |
| `Cmd/Ctrl + C` | 選んでいる文字をコピーする。文字を選んでいなければ、画面ごとに決めた値（「キーボードからコピーする」） |

**確認の表示が出ている間は、`Esc` が「やめる」と同じ動きをする。**
